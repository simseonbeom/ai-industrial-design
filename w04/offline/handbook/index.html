PART 01 — Understanding the Web: 제품 디자인에서 디지털 경험으로

01 · UNDERSTANDING THE WEB & PORTFOLIO PLANNING

Week 04 — Offline · AI × Industrial Design

안녕하세요, 4주차 오프라인 수업 시작하겠습니다. 오늘은 조금 다른 이야기를 해요.

지난 3주 동안은 제품 자체를 디자인했죠. 형태를 잡고, CMF를 정하고, 사용 경험까지 설계했어요. 오늘은 그렇게 만든 제품을 "어떻게 보여 줄 것인가", 즉 웹사이트와 포트폴리오를 기획합니다.

오른쪽 의자는 오늘 계속 쓸 예시 제품, 크림색 부클레 라운지체어예요. 이 의자 하나를 소개하는 웹사이트를 처음부터 기획해 볼 거예요.

그리고 오늘은 코딩을 하지 않습니다. 코드는 다음 온라인 수업에서 AI가 만들어 줄 거고, 오늘 우리는 "무엇을, 어떤 순서로, 어떻게 보여 줄지"를 결정하는 디자이너의 일을 합니다.

02 · FROM PRODUCT TO WEB

제품 디자인에서 웹으로

지금까지의 흐름을 한번 짚고 갈게요. 1주차에 스케치로 콘셉트를 만들었고, 2주차에 형태와 CMF, 디테일, Hero 이미지까지 다듬었어요. 3주차에는 사람이 이 제품을 어떻게 쓰는지, 사용 경험과 제품 영상을 설계했죠.

그러면 이제 남은 질문은 하나예요. "이걸 누군가에게 어떻게 보여 줄 거냐." 교수님, 면접관, 클라이언트, 혹은 그냥 내 작업을 처음 보는 사람이요.

그게 오늘 다룰 디지털 경험, 웹사이트입니다. 제품 디자인에서 했던 사고방식을 화면으로 그대로 가져가는 거라고 생각하시면 돼요.

03 · TODAY'S GOAL

오늘의 목표

오늘 목표는 세 가지예요. 먼저 웹이 뭔지, 웹사이트가 어떻게 동작하는지 큰 그림으로 이해하고요. 다음으로 잘 만든 포트폴리오 사이트를 보면서 "왜 좋은지"를 구조적으로 읽어 내는 연습을 하고요. 마지막으로 내 프로젝트를 위한 웹사이트를 직접 기획합니다.

오늘 끝날 때 손에 남는 건 Website Planning Board 한 장이에요. 이 보드가 중요한 이유는, 다음 주 온라인 수업에서 심선범 강사님과 AI로 실제 웹사이트를 만들 때 이게 그대로 설계도가 되기 때문이에요. 기획이 탄탄할수록 AI 결과물도 좋아집니다.

04 · WHAT IS THE WEB?

웹이란 무엇인가

인터넷과 웹, 같은 말처럼 쓰지만 사실 달라요. 인터넷은 전 세계 컴퓨터를 연결한 네트워크, 말하자면 도로망이에요. 카톡, 이메일, 온라인 게임도 다 이 도로를 써요.

웹은 그 도로 위에 지어진 건물들이라고 생각하면 돼요. 크롬이나 사파리 같은 브라우저로 여는 페이지들, 그리고 그 페이지들이 링크로 서로 이어진 공간이 웹이에요.

그러니까 웹사이트는 "주소로 찾아가서, 브라우저로 열어 보는, 링크로 연결된 페이지 묶음"이에요. 오늘 우리가 기획할 포트폴리오도 결국 이 건물 하나를 짓는 일입니다.

05 · WHY DESIGNERS NEED A WEBSITE

디자이너에게 웹사이트가 필요한 이유

그럼 디자이너한테 왜 웹사이트가 필요할까요. 첫째, 링크 하나면 끝이에요. 파일 보내고 용량 걱정할 필요 없이 언제든 열려요.

둘째, 이야기를 담을 수 있어요. PDF는 페이지 수 제약이 있지만, 웹은 스케치부터 최종 결과까지 과정을 길게 풀 수 있어요.

셋째, 3주차에 만든 제품 영상처럼 움직이는 결과물을 그대로 넣을 수 있죠.

넷째가 제일 중요한데요, 사이트 자체가 내 디자인 감각을 보여 줘요. 여백을 어떻게 썼는지, 사진을 어떤 순서로 보여 주는지, 그게 다 평가 대상이에요. 그래서 오늘 기획이 중요합니다.

06 · PRODUCT DESIGN ≈ WEB DESIGN

제품 디자인과 웹 디자인은 같은 사고를 쓴다

여기서 안심하셔도 되는 게, 웹 디자인이 완전히 새로운 분야가 아니에요. 여러분이 해 온 제품 디자인의 사고를 그대로 쓸 수 있어요.

형태와 비례를 잡던 감각은 레이아웃과 그리드가 되고요, CMF는 화면의 컬러와 타이포, 이미지 톤이 돼요. 3주차 사용 시나리오는 사용자가 사이트를 어떤 순서로 둘러보는지, 사용자 흐름이 되고요. 인터랙션은 버튼과 스크롤 반응이 되고, Hero Image는 사이트의 첫 화면이 됩니다.

재료만 바뀌는 거예요. 의자가 오크와 부클레로 만들어진다면, 웹사이트는 레이아웃과 글자와 이미지로 만들어지는 거죠.

07 · TYPES OF WEBSITES

웹사이트의 종류

웹사이트는 목적에 따라 종류가 나뉘어요. 포트폴리오, 프로젝트 하나를 깊게 보여 주는 케이스 스터디, 제품 하나를 소개하는 랜딩 페이지, 브랜드 사이트, 쇼핑몰.

우리가 오늘 기획할 건 앞의 세 개가 섞인 형태예요. 메인에서 나를 소개하고 작업 목록을 보여 주고, 라운지체어 프로젝트를 누르면 그 제품의 과정과 결과를 깊게 보여 주는 상세 페이지로 들어가는 구조요.

브랜드 사이트나 쇼핑몰은 레퍼런스로는 참고할 수 있지만, 우리 목적과는 달라요. 목적이 다르면 구조가 달라진다, 이것만 기억해 주세요. 여기까지 PART 01이었습니다.

PART 02 — How Websites Work: 서버 · 도메인 · HTML/CSS/JS · 반응형

08 · HOW WEBSITES WORK

PART 02

PART 02로 넘어갈게요. 이번 파트는 45분 정도예요. 여기서는 웹사이트가 실제로 어떻게 동작하는지를 봅니다.

걱정하실 필요는 없어요. 코드를 짜는 게 아니라 "읽어 보는" 수준이에요. 개발자와 대화할 때, 그리고 다음 주에 AI에게 웹사이트를 만들어 달라고 할 때 이 개념들을 알면 훨씬 정확하게 말할 수 있어요.

09 · CLIENT & SERVER

브라우저와 서버

웹의 기본 구조는 아주 단순해요. 클라이언트와 서버, 둘이 있어요. 클라이언트는 여러분 컴퓨터나 휴대폰의 브라우저고요, 서버는 웹사이트 파일이 저장되어 있는 인터넷 어딘가의 컴퓨터예요.

브라우저가 "이 페이지 주세요" 하고 요청을 보내면, 서버가 그 페이지를 만드는 파일들, HTML, CSS, 이미지 같은 걸 돌려줘요. 이게 응답이에요.

식당으로 생각하면 쉬워요. 손님이 주문하면 주방이 음식을 내 주죠. 웹사이트를 연다는 건 결국 이 주문과 서빙이 빠르게 일어나는 거예요.

10 · DOMAIN · HOSTING · FILES

웹사이트에 필요한 세 가지

웹사이트 하나가 인터넷에 존재하려면 세 가지가 필요해요. 도메인, 호스팅, 그리고 파일이에요.

도메인은 주소예요. studio-name.com 같은, 사람이 기억하기 쉬운 이름이죠. 호스팅은 그 파일들을 올려 두는 서버 공간, 집으로 치면 땅과 건물이에요. 파일은 그 안을 채우는 가구와 인테리어고요.

옛날엔 이걸 하나하나 따로 준비해야 했는데, 요즘은 AI 웹 빌더가 파일 만드는 것부터 호스팅까지 한 번에 해 줘요. 다음 주 온라인 수업이 바로 그거예요. 그래서 여러분이 정말 고민해야 하는 건 "그 안에 무엇을 어떻게 담을지", 즉 가구 배치예요.

11 · WHAT HAPPENS WHEN YOU OPEN A PAGE

주소를 입력하면 일어나는 일

이번엔 주소창에 주소를 치고 엔터를 누르는 순간 무슨 일이 일어나는지 다섯 단계로 볼게요.

주소를 입력하면, 브라우저가 먼저 그 도메인이 어느 서버에 있는지 찾아요. 이걸 DNS라고 하는데, 이름만 알아 두시면 돼요. 서버를 찾으면 페이지를 요청하고, 서버가 파일을 보내 주고, 마지막으로 브라우저가 그 파일을 읽어서 화면으로 조립해요. 이걸 렌더링이라고 해요.

이게 1~2초 안에 다 일어나요. 그런데 디자이너가 알아야 할 포인트가 하나 있어요. 4번, 파일 전달 단계에서 이미지가 너무 크면 시간이 오래 걸려요. 고해상도 렌더 이미지를 그대로 올리면 첫 화면이 늦게 떠요. 포트폴리오에서 첫인상은 3초 안에 결정되니까, 이미지 용량은 꼭 신경 써 주세요.

12 · HTML · CSS · JAVASCRIPT

화면을 만드는 세 가지 언어

서버가 보내 주는 파일 중 핵심은 세 가지 언어예요. HTML, CSS, 자바스크립트.

의자로 비유해 볼게요. HTML은 구조예요. 의자의 프레임처럼, 제목이 있고 그 아래 이미지가 있고 버튼이 있다는 뼈대를 정해요. CSS는 표현이에요. 같은 프레임이라도 부클레를 씌우느냐 가죽을 씌우느냐에 따라 완전히 달라 보이죠. 색, 글꼴, 여백이 여기서 정해져요. 자바스크립트는 동작이에요. 버튼을 누르면 뭔가 열리고, 스크롤하면 이미지가 바뀌는 반응이요.

디자이너로서 여러분이 주로 결정하는 건 앞의 두 개예요. 무엇을 어떤 순서로 둘지, 그리고 어떻게 보이게 할지. 다음 장에서 실제 코드를 한번 읽어 볼게요. 짜는 게 아니라 읽기만 해요.

13 · READING THE CODE

코드 읽어 보기 · 짜지 않고 읽기만

자, 겁먹지 마시고 그냥 읽어만 볼게요. 라운지체어 소개 화면 하나를 만드는 코드예요.

왼쪽 HTML부터 볼게요. section 안에 img, h1, p, button이 차례로 있죠. 그러니까 "이미지, 제목, 설명, 버튼이 이 순서로 있다"는 뜻이에요. 꺾쇠 안의 단어가 각각 무엇인지를 말해 줘요.

가운데 CSS는 표현이에요. hero 영역 배경은 크림색, 여백 80픽셀, 제목은 48픽셀에 진한 브라운, 버튼은 모서리를 둥글게. 읽어 보면 거의 디자인 스펙 문서랑 똑같아요.

오른쪽 자바스크립트는 동작이에요. 버튼을 클릭하면 상세 영역으로 부드럽게 스크롤해라.

보시면 알겠지만, 각 줄이 결국 디자인 결정이에요. "버튼은 둥글게", "클릭하면 아래로 부드럽게." 다음 주에 AI에게 이 문장을 말로 전달하면, AI가 이 코드를 써 줘요. 그래서 오늘 기획을 정확하게 할수록 다음 주 결과물이 정확해집니다.

HTML

<section class="hero">
  <img src="chair.jpg"
     alt="Bouclé Lounge Chair">
  <h1>Bouclé Lounge Chair</h1>
  <p>부드러운 곡선의 1인 라운지체어</p>
  <button>자세히 보기</button>
</section>

CSS

.hero {
  background: #F4F0EA;
  padding: 80px;
}
h1 {
  font-size: 48px;
  color: #2B2622;
}
button {
  border-radius: 24px;
}

JS

const btn =
  document.querySelector('button');

btn.addEventListener('click', () => {
  detail.scrollIntoView({
    behavior: 'smooth'
  });
});

14 · RESPONSIVE WEB

하나의 사이트, 여러 개의 화면

마지막으로 반응형이라는 개념이에요. 같은 사이트가 컴퓨터, 태블릿, 휴대폰에서 각각 다르게 배치돼요. 데스크톱에서는 메뉴가 쭉 펼쳐져 있다가, 모바일에서는 햄버거 메뉴, 줄 세 개짜리 아이콘으로 접히죠. 이미지와 글도 가로로 나란히 있다가 세로로 쌓여요.

중요한 건, 포트폴리오를 처음 보는 사람 중 상당수가 휴대폰으로 링크를 연다는 거예요. 카톡으로 링크 받으면 그냥 폰으로 열잖아요. 그래서 오늘 와이어프레임을 그릴 때도 데스크톱 하나만 그리지 말고 모바일도 같이 생각할 거예요. 여기까지 PART 02였습니다. 잠깐 쉬었다 갈게요.

PART 03 — Web Design Fundamentals: 레이아웃 · 타이포 · 컬러 · 위계 · 내비게이션

15 · WEB DESIGN FUNDAMENTALS

PART 03

PART 03, 웹 디자인 기본 요소예요. 30분 정도 진행합니다.

앞에서 제품 디자인과 웹 디자인이 같은 사고를 쓴다고 했죠. 여기서는 화면을 만드는 재료 다섯 가지, 레이아웃, 타이포, 컬러와 이미지, 위계와 여백, 내비게이션을 하나씩 짚어요. 각각 라운지체어 사이트에 어떻게 적용되는지 같이 볼게요.

16 · LAYOUT & GRID

보이지 않는 질서

첫 번째 재료는 레이아웃과 그리드예요. 화면 위에 투명한 세로 칸들이 깔려 있다고 생각해 보세요. 웹에서는 보통 12칸을 많이 써요.

칸을 컬럼, 칸 사이 간격을 거터, 화면 가장자리 여백을 마진이라고 해요. 예시를 보면 왼쪽에 텍스트가 6칸, 오른쪽에 의자 이미지가 5칸 정도를 차지하죠.

제품 디자인에서 비례가 맞으면 정돈되어 보이듯이, 화면도 요소들이 이 칸에 맞춰 있으면 깔끔해 보여요. 와이어프레임 그릴 때도 이 그리드를 염두에 두고 그리시면 됩니다.

17 · TYPOGRAPHY

글자의 크기가 곧 순서다

두 번째는 타이포그래피예요. 웹에서는 글자 크기가 곧 읽는 순서예요. 큰 제목을 먼저 보고, 그 다음 섹션 제목, 그 다음 본문, 마지막에 캡션을 봐요.

기준 크기를 보면, 메인 제목은 48에서 72픽셀, 섹션 제목은 32에서 40, 본문은 16에서 18, 캡션은 12에서 14 정도예요. 크기 단계는 3~4개면 충분하고, 글꼴도 한두 개면 돼요. 너무 많으면 산만해져요.

그리고 글꼴 선택은 CMF 고르듯이 하시면 돼요. 이 의자처럼 둥글고 부드러운 제품이라면, 날카로운 글꼴보다 여유 있는 글꼴이 어울리겠죠.

18 · COLOR & IMAGE

제품의 CMF에서 화면의 색을 가져온다

세 번째는 컬러와 이미지예요. 여기서 꿀팁 하나 드릴게요. 사이트 색을 새로 고민하지 마시고, 제품의 CMF에서 그대로 뽑아 오세요.

이 의자라면 부클레의 크림색을 배경으로, 한 톤 어두운 샌드를 면 구분에, 오크 다리 색을 포인트로, 진한 브라운을 글자와 버튼에 써요. 비율은 대략 70, 20, 5, 5 정도요.

그리고 포트폴리오에서 이미지는 주인공이에요. 2주차에 만든 이미지들, 조명과 배경 톤이 들쭉날쭉하면 사이트가 산만해 보여요. 같은 톤으로 맞춰 두면 사이트 전체가 하나의 제품처럼 보입니다. 참고로 왼쪽 텍스처 이미지는 설명용으로 AI가 만든 예시예요.

19 · HIERARCHY & WHITESPACE

무엇을 먼저 보게 할 것인가

네 번째는 위계와 여백이에요. 두 화면을 비교해 볼게요. 왼쪽은 보여 주고 싶은 게 많아서 이미지 세 장, 긴 제목, 긴 본문, 버튼 세 개를 다 넣었어요. 그런데 어디부터 봐야 할지 모르겠죠.

오른쪽은 제목, 의자, 버튼 하나. 여백이 많은데도 오히려 의자가 훨씬 고급스러워 보여요. 시선이 위에서 아래로 자연스럽게 흘러요.

산업디자인 하시는 분들은 이 감각 이미 있으실 거예요. 제품 사진 찍을 때도 배경을 비우잖아요. 웹도 똑같아요. 한 화면에 하나의 메시지. 이것만 지켜도 포트폴리오 수준이 확 올라갑니다.

20 · NAVIGATION & INTERACTION

길을 잃지 않게 하는 장치

마지막 다섯 번째 재료는 내비게이션과 인터랙션이에요.

내비게이션은 길 안내예요. 메뉴는 3개에서 5개 정도. 포트폴리오라면 Work, About, Contact 정도면 충분해요. CTA는 행동 유도 버튼인데, "프로젝트 보기", "연락하기"처럼 다음 행동을 알려 주는 거예요. 한 화면에 주 버튼은 하나만 두세요.

스크롤은 이야기의 순서고, 피드백은 마우스를 올리거나 눌렀을 때의 반응이에요.

3주차 기억나시죠? 사용자 행동, 제품 반응, 사용자 피드백. 웹도 똑같아요. 사용자가 버튼을 누르면, 화면이 반응하고, 사용자가 그걸 알아차리는 것. 여러분이 이미 설계해 본 구조입니다. 여기까지 PART 03이었습니다.

PART 04 — Portfolio Reference Analysis: 레퍼런스를 다섯 관점으로 읽기

21 · PORTFOLIO REFERENCE ANALYSIS

PART 04

PART 04, 포트폴리오 레퍼런스 분석이에요. 40분 정도 진행하고, 중간에 직접 분석하는 실습이 있어요.

여기서 목표는 "이 사이트 예쁘다"에서 멈추지 않고, 왜 좋은지를 말로 설명할 수 있게 되는 거예요. 그래야 내 사이트에 가져올 수 있거든요.

22 · WHY REFERENCES

따라 하기가 아니라 읽어 내기

레퍼런스를 보는 방법은 두 가지가 있어요. 하나는 "이 사이트처럼 만들어 주세요", 따라 하기예요. 이러면 겉모습만 옮겨 와서 내 제품이랑 안 맞기도 하고, 결국 남의 사이트랑 똑같아져요.

다른 하나는 분석이에요. "첫 화면에 제품 사진 한 장만 크게 둬서 제품이 주인공이 되게 했다." 이렇게 이유를 문장으로 정리하면, 그 원리만 가져와서 내 의자에 맞게 다시 쓸 수 있어요.

그리고 이 문장이 다음 주에 그대로 AI에게 주는 지시문이 돼요. AI한테 "이 사이트처럼"이라고 하면 엉뚱한 게 나오지만, "첫 화면에 제품 사진 한 장, 여백 넓게"라고 하면 정확하게 나와요.

23 · THREE PORTFOLIO PATTERNS

포트폴리오 사이트의 세 가지 패턴

디자이너 포트폴리오 사이트를 많이 보다 보면 크게 세 가지 패턴이 보여요.

A는 갤러리형이에요. 작업 썸네일을 격자로 쭉 깔아요. 프로젝트가 여러 개일 때 한눈에 보여 주기 좋아요.

B는 케이스 스터디형이에요. 프로젝트 하나를 길게 스크롤하면서, 문제, 콘셉트, 과정, 결과 순서로 이야기해요. 산업디자인 포트폴리오에서 제일 중요한 형식이에요.

C는 제품 랜딩형이에요. 제품 하나를 크게, 정보는 적게. 브랜드 제품 페이지 같은 느낌이죠.

우리는 이걸 섞어 쓸 거예요. 메인은 갤러리, 라운지체어 상세 페이지는 케이스 스터디, 그리고 상세 페이지 첫 화면 분위기는 랜딩형처럼. 실습 때 레퍼런스를 찾을 때도 이 세 패턴 중 뭔지 먼저 구분해 보세요.

24 · ANALYSIS FRAMEWORK

다섯 가지 관점으로 읽는다

레퍼런스를 볼 때는 이 다섯 가지 관점으로 나눠서 보세요. 구조, 레이아웃, 타이포그래피, 이미지와 컬러, 인터랙션. 앞 PART 03에서 배운 재료들이랑 같죠.

각 관점마다 "무엇을, 왜"를 한 문장으로 적는 게 핵심이에요. 예를 들어 "깔끔하다"라고 쓰면 분석이 아니에요. "배경을 거의 흰색으로 두고 글꼴을 하나만 써서 이미지가 돋보인다", 이렇게 무엇이 그렇게 보이게 만드는지를 적어야 해요.

처음엔 어려워도, 다섯 칸을 채우다 보면 자연스럽게 눈이 생겨요.

25 · EXAMPLE ANALYSIS

분석 예시 · 케이스 스터디 페이지

예시를 하나 같이 분석해 볼게요. 라운지체어를 주제로 한 케이스 스터디 페이지라고 가정한 화면이에요. 실제 사이트가 아니라 설명용 목업입니다.

구조부터 보면, Hero 이미지, 콘셉트, 소재, 사용 장면 순서로 내려가요. 3주차에 짠 사용 시나리오 흐름이랑 거의 같죠.

레이아웃은 첫 화면에 이미지 한 장을 꽉 채우고, 아래쪽은 글이 좁고 이미지가 넓어요.

타이포는 제목은 크고 굵게, 섹션 번호는 작은 대문자에 오크색 포인트.

이미지와 컬러는 모든 사진이 같은 따뜻한 오후 빛이고, 크림 배경이랑 톤이 맞아요.

인터랙션은 스크롤하면 섹션이 하나씩 나타나고 메뉴는 위에 고정.

이렇게 다섯 줄이 나오면 분석 끝이에요. 다음 장에서 여러분이 직접 해 봅니다.

26 · REFERENCE ANALYSIS

PRACTICE 01

실습 1번, 레퍼런스 분석이에요. 산업디자인이나 제품디자인 포트폴리오 사이트를 세 개 찾아 주세요. Behance, 디자이너 개인 사이트, 디자인 스튜디오 사이트 다 괜찮아요.

먼저 각 사이트가 갤러리형인지, 케이스 스터디형인지, 랜딩형인지 표시하고요, 다섯 가지 관점으로 한 문장씩 적어 주세요. 화면 캡처도 같이 붙여 두시고요.

마지막으로 내 사이트에 가져오고 싶은 것 두 개, 피하고 싶은 것 하나를 골라 주세요. 이 KEEP과 AVOID가 오늘 기획 보드에 그대로 들어가요.

[진행] 진행하면서 돌아다니며 "예쁘다, 깔끔하다" 같은 문장이 보이면 "무엇이 그렇게 보이게 하나요?"라고 다시 물어봐 주세요.

27 · FROM REFERENCE TO DIRECTION

레퍼런스에서 나의 방향으로

분석이 끝났으면 내 방향으로 바꿔야 해요. KEEP, ADAPT, AVOID 세 칸으로 정리하면 쉬워요.

라운지체어 예시로 보면, KEEP은 "첫 화면은 제품 사진 한 장", "섹션 번호 라벨". ADAPT는 원리는 가져오되 내 제품에 맞게 바꾸는 거예요. 레퍼런스가 흰 배경이었다면 우리는 부클레 크림 배경으로, 차가운 조명이었다면 따뜻한 오후 빛으로. AVOID는 한 화면에 이미지 여러 장 나열하기.

그리고 이걸 키워드 서너 개로 압축해요. 이 의자는 Soft, Warm, Quiet, Tactile. 이 키워드가 기획 보드의 비주얼 방향이 되고, 다음 주 AI 프롬프트에도 그대로 들어가요. 여기까지 PART 04였습니다.

PART 05 — IA & Wireframe: 사이트맵과 와이어프레임 설계

28 · IA & WIREFRAME

PART 05

PART 05, 정보 구조와 와이어프레임이에요. 오늘 수업에서 제일 긴 50분 파트고, 실제 설계를 하는 핵심 파트예요.

두 가지를 해요. 하나는 IA, 사이트 전체에 어떤 페이지가 있는지 지도를 그리는 거고요, 다른 하나는 와이어프레임, 한 페이지 안에 무엇이 어떤 순서로 놓이는지 뼈대를 그리는 거예요. 제품으로 치면 IA는 전체 구성도, 와이어프레임은 단면 스케치 같은 거예요.

29 · INFORMATION ARCHITECTURE

사이트의 지도

IA, Information Architecture, 정보 구조예요. 쉽게 말해 사이트의 지도예요.

맨 위에 HOME이 있고, 그 아래 메인 메뉴로 WORK, ABOUT, PROCESS, CONTACT가 있어요. WORK 아래에 프로젝트 상세 페이지들이 달려요. 라운지체어 프로젝트, 그리고 1~3주차에 했던 램프 프로젝트 같은 거요.

몇 가지 원칙만 기억하세요. 메인 메뉴는 3~5개, 깊이는 2단계 안쪽. 어떤 페이지든 세 번 클릭 안에 도착할 수 있게. 그리고 욕심내지 말고 작게 시작하세요. 프로젝트 하나, 두 개로 시작해도 충분해요. 다음 주에 한 번에 다 만들어야 하니까요. PROCESS 같은 메뉴는 필요 없으면 빼도 돼요.

30 · CONTENT INVENTORY

내가 가진 재료부터 확인한다

구조를 짜기 전에 재료부터 확인해요. 콘텐츠 인벤토리라고 하는데, 그냥 내가 가진 걸 다 펼쳐 놓는 거예요.

여러분은 이미 재료가 많아요. 1주차 스케치, 2주차 Refined Concept, CMF, 디테일, Multi-view, Hero 이미지, 3주차 시나리오와 제품 영상. 이게 각각 사이트의 어느 섹션에 들어갈지 매칭해 보세요.

그리고 부족한 것도 적어요. 보통 연락처, 프로필 사진, 프로젝트를 한 줄로 설명하는 문장이 없어요. 이건 다음 주 전까지 준비해 오셔야 해요.

순서가 중요해요. 섹션을 먼저 정하고 재료를 찾으면 빈칸이 생겨요. 재료를 먼저 펼쳐 놓고 섹션을 정하세요.

31 · PAGE STORY

프로젝트 페이지는 하나의 이야기다

이제 라운지체어 프로젝트 상세 페이지 하나를 이야기로 짜 볼게요. 위에서 아래로 스크롤하면서 읽히는 순서예요.

첫 화면 HERO에서 제품 사진과 한 줄 소개. 그 다음 CONCEPT, 왜 이 의자를 만들었고 누구를 위한 건지. PROCESS에서 스케치부터 다듬는 과정. DESIGN에서 형태와 디테일. MATERIAL에서 CMF. EXPERIENCE에서 3주차 사용 장면과 영상. OUTCOME에서 최종 이미지. 마지막 NEXT에서 다른 프로젝트 보기나 연락하기.

각 칸 아래 금색 글씨가 그 섹션에 들어갈 재료의 출처예요. 앞 장 인벤토리랑 연결되죠.

3주차 스토리보드 짤 때처럼 시작, 전개, 결말이 있어야 해요. 특히 첫 화면 3초가 계속 볼지 말지를 결정하고, 마지막 섹션이 다음 행동을 결정해요. 이 여덟 개가 기본형이고, 재료에 따라 빼거나 합쳐도 됩니다.

32 · WHAT IS A WIREFRAME

화면의 뼈대 스케치

와이어프레임은 화면의 뼈대 스케치예요. 정밀도에 따라 세 단계가 있어요.

로우 피델리티는 박스와 선만으로 위치와 순서를 정하는 단계예요. 이미지 자리는 엑스자 박스, 글자는 회색 선. 미드 피델리티는 실제 문구와 글자 크기가 들어가고, 하이 피델리티는 실제 이미지, 컬러, 글꼴까지 들어간 완성 시안이에요.

오늘 우리는 로우 피델리티까지만 해요. 색이랑 이미지는 다음 주에 AI가 입혀 줄 거예요. 오늘 손으로 정할 건 딱 하나, "무엇이 어디에, 어떤 순서로"예요. 제품 디자인에서 렌더링 전에 형태 스케치부터 하는 것과 같아요.

33 · DESKTOP WIREFRAME

라운지체어 페이지 · 데스크톱 와이어프레임

앞에서 짠 페이지 스토리를 실제 와이어프레임으로 옮기면 이렇게 돼요. 로우 피델리티예요. 색도 사진도 없고 박스뿐이죠.

맨 위에 상단 고정 메뉴. 그 아래 HERO는 화면을 꽉 채우는 제품 사진이랑 제목, 한 줄 소개. CONCEPT는 왼쪽에 글, 오른쪽에 스케치, 비율은 4대 6 정도. DESIGN과 MATERIAL은 이미지 세 장을 나란히 놓는 3열 그리드. EXPERIENCE는 3주차 영상을 전체 폭으로. 마지막에 이전 프로젝트 링크와 연락하기 버튼.

오른쪽 금색 라벨처럼, 각 박스에 이름과 짧은 메모를 꼭 붙여 주세요. 다음 주에 AI한테 이걸 설명할 때 이 메모가 그대로 지시문이 돼요.

34 · MOBILE WIREFRAME

같은 페이지 · 모바일 와이어프레임

같은 페이지를 모바일로 그리면 이렇게 돼요. 원칙 네 가지만 기억하세요.

첫째, 가로로 나란히 있던 건 세로로 쌓아요. 글과 이미지가 옆에 있었다면 이미지가 위, 글이 아래로.

둘째, 메뉴는 햄버거 아이콘으로 접어요.

셋째, 우선순위가 낮은 건 줄여요. 3열 이미지 그리드는 1열로, 이미지 수도 줄이고요.

넷째, 버튼은 손가락으로 누르기 좋게 충분히 크게.

앞에서 말했듯이 포트폴리오 링크는 휴대폰으로 많이 열려요. 실습할 때 데스크톱 옆에 모바일도 꼭 같이 그려 주세요. 거창하게 그릴 필요 없이 박스 순서만 보여 주면 돼요.

35 · SITEMAP & WIREFRAME

PRACTICE 02

실습 2번이에요. 오늘 핵심 실습이니까 시간 넉넉하게 드릴게요.

순서대로 가요. 먼저 1~3주차 결과물을 펼쳐 놓고 어느 섹션에 들어갈지 분류해 주세요. 그 다음 사이트맵, HOME 아래 메뉴 3~5개와 프로젝트 페이지 연결. 그 다음 프로젝트 페이지 섹션 순서. 마지막으로 와이어프레임, 데스크톱 한 장, 모바일 한 장이요.

손으로 그리셔도 되고, 박스 위주로 빠르게 그리세요. 예쁘게 그리는 시간이 아니라 순서를 정하는 시간이에요. 박스마다 이름이랑 짧은 메모 꼭 달아 주시고요.

[진행] 돌아다니면서 "이 섹션에 들어갈 재료가 실제로 있나요?"를 확인해 주세요. 재료가 없는 섹션은 빼거나 다음 주 전까지 준비할 목록으로 옮기게 해 주세요.

37 · WEBSITE PLANNING BOARD

오늘의 결과물 · 여덟 칸

이게 오늘의 최종 결과물, Website Planning Board예요. 여덟 칸이에요.

윗줄 네 칸은 전략이에요. 사이트 목적, 보는 사람, 첫 화면의 핵심 메시지, 레퍼런스. 아랫줄 네 칸은 설계예요. 사이트맵, 섹션 순서, 와이어프레임, 비주얼 방향.

중요한 건 윗줄이 아랫줄의 근거가 된다는 거예요. 예를 들어 보는 사람이 면접관이라면, 바쁘니까 첫 화면에서 바로 대표 작업이 보여야 하겠죠. 그럼 와이어프레임이 달라져요. 전략 없이 와이어프레임부터 그리면 "왜 이렇게 했어요?"라는 질문에 답을 못 해요.

38 · BOARD EXAMPLE

작성 예시 · 라운지체어 포트폴리오

라운지체어로 채운 예시예요. 목적은 졸업 포트폴리오, 제품 하나의 과정을 깊게 보여 주는 것. 보는 사람은 디자인 스튜디오 면접관, 짧은 시간에 판단하는 사람이에요. 그래서 핵심 메시지는 짧게, "Soft form, quiet comfort."

레퍼런스에서 KEEP은 사진 한 장짜리 Hero와 섹션 번호, AVOID는 이미지 나열. 사이트맵은 HOME, WORK, ABOUT, CONTACT 네 개. 섹션 순서는 Hero부터 Next까지. 와이어프레임은 아까 본 데스크톱 한 장, 모바일 한 장. 비주얼 방향은 키워드 네 개랑 크림, 오크, 딥브라운.

보드에는 대표 이미지도 두세 장 붙여 주세요. 다음 주에 AI 웹 빌더에 그대로 올릴 이미지들이에요. 참고로 이 의자 이미지는 설명용으로 AI가 만든 예시예요. 여러분은 2~3주차에 만든 본인 이미지를 쓰시면 돼요.
